# UO AI Executive Summary

The `uoaisummary` widget generates a bilingual company-level operating summary from the four UO dashboard sources. Japanese is shown by default. The language button switches to Simplified Chinese generated by the same model response, so changing languages does not make another model request.

## Configuration

Configure this deployment directly in the local `config/services.yaml`. That file is Git-ignored and must remain local: do not commit, paste, or share its deployed URL or key. The values below are synthetic placeholders only. Replace them locally with the approved deployment values.

Place the service in `リアルタイム看板` before the shipping dashboard service:

```yaml
- AI 経営サマリー:
    icon: mdi-creation
    widget:
      type: uoaisummary
      apiUrl: "https://ai-gateway.example.invalid/v1/responses"
      apiKey: "replace-with-local-api-key"
      model: "gpt-5.6-luna"
      reasoningEffort: xhigh
      generationInterval: 3600000
      manualCooldown: 600000
      requestTimeout: 180000
      refreshInterval: 60000
```

`apiUrl` must be the complete HTTP or HTTPS Responses endpoint, end in `/responses`, and have no query string or fragment. `apiKey` is sent as the Bearer credential. This deployment accepts `gpt-5.6-luna` with `reasoningEffort: xhigh` only.

The timing fields are milliseconds:

- `generationInterval`: minimum interval between successful automatic generations; one hour by default.
- `manualCooldown`: cooldown after an accepted manual request; ten minutes by default.
- `requestTimeout`: timeout for one model request; three minutes by default.
- `refreshInterval`: normal browser polling interval for the cached public summary. It does not control model generation.

Only `refreshInterval` is exposed to the browser. The endpoint, key, model, reasoning setting, generation interval, cooldown, and model timeout remain server-only.

## Schedule and manual refresh

The Node server restores the local cache at startup and schedules the next run from its saved deadline. If there is no usable cached result, generation starts in the background immediately. A successful automatic or manual run schedules the next automatic run one hour later.

The `立即重新分析` / reanalysis button submits background work and returns immediately. Manual requests have a ten-minute cooldown. Automatic work, manual work, and concurrent clicks share one in-process task lock, so only one collection and model request sequence can run at a time. While a run is active, the last good summary remains visible.

## Data and privacy

The server reads shipping, operating attention, Rakuten sales, and company performance through their existing read-only endpoints. It normalizes facts and renders business numbers from server-owned metric keys; model prose is not the source of displayed numbers.

Low-rating review samples are treated as untrusted data. Before model submission they are capped at ten, truncated to 300 characters each, and stripped of buyer identifiers, contact details, order and review identifiers, URLs, control text, and prompt-like instructions. Raw ranking payloads are reduced to a small deduplicated product set.

The browser and summary cache never receive the API credential, private model URL, raw model request or response, buyer identifiers, review URLs, or unredacted review text. Do not log or copy these private values when troubleshooting.

## Failure states

- Four valid sources produce a complete analysis.
- Two or three valid sources, or any internally partial source, produce a partial analysis with the missing coverage shown.
- Fewer than two valid sources skip the model request. The last good summary stays visible as stale when available; otherwise the widget shows an error state.
- A retryable timeout, network failure, temporary HTTP response, or invalid model structure is retried once. A second failure retains the last good summary as stale.
- Configuration and authentication failures are not retried. Correct the local configuration, then use manual reanalysis or restart the single server process.

Public errors contain only a safe category such as `configuration`, `source_timeout`, `source_unavailable`, `model_timeout`, `model_http`, `model_schema`, `cache`, or `unexpected`.

## Cache recovery

The local cache is `config/uo-ai-summary.json`, which is also Git-ignored. Writes use a temporary file and atomic rename. Only validated bilingual summaries, safe display metrics, usage counts, and up to 24 compact snapshots are retained; raw reviews and model bodies are not stored.

If the cache contains invalid JSON, startup automatically renames it with a `.corrupt-<timestamp>` suffix, starts from a clean state, and submits background regeneration. For manual recovery, stop the server process, move the cache aside to a private local backup, and start the process again. Do not commit or share the cache or its corrupt backup.

## Single-process scheduling

The scheduler and task lock coordinate one Node process only. Run a single Homepage server process for this release. Before deploying multiple replicas, add an external shared lock or move scheduling to a dedicated task system; otherwise each replica can generate independently.
